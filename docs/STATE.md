# 키트의 상태

키트 저장소에서 에이전트가 한 일과 이어서 할 일을 적는다. 세션 시작 때 "다음 할 일"의 첫 항목이 자동으로 안내된다.

## 지금까지 한 일

- 2026-11-16: 키트를 처음 만들었다. 플러그인(스킬 4개, 서브에이전트 2개, 세션 시작 훅), 도구 목록과 반영 정책, 서버 준비물, 형식 검증 스크립트.
- 2026-11-16: 서버가 생기기 전까지 쓸 클라우드 예약 작업을 등록했다. 매주 목요일 오후 2시(한국 시간)에 `scout`를 돌리고(처음에는 월요일 오전 4시였고 같은 날 바꿈), 변경 제안은 만들되 병합하지 않는다. 관리 화면은 claude.ai의 예약 작업 목록(이름: vibe-kit 주간 scout).

- 2026-11-16: 사용자 요청으로 ECC의 세 기능을 옮겼다. 계속 배우기(교정으로 보이는 말에 반응하는 훅, 확신 점수, 세션 시작 때 확신 높은 배움 안내)와 먼저 찾아보고 만들기(`freshness`에 절 추가, `AGENTS.md` 본에 한 줄)는 생각만 가져와 다시 만들었고, 디자인 스킬은 따로 시험해 도구 목록에 반영한다.

- 2026-11-16: 사용자 지시로 라이선스 규칙을 더했다(상업적 이용을 허용하는 라이선스가 명시된 것만 채택, 검증 스크립트가 검사). 라이선스가 없는 apple-design-skill, mobile-app-ui-design과 출처를 확인하지 못한 design-taste-frontend를 제외했다. `scout`에 "비교 전에 시험이 제대로 됐는지 확인"을, `retro`에 "지시 파일이 지금도 맞는지 확인"을 더했다.

- 2026-11-17: 사용자가 실제 프로젝트에서 `setup`을 다시 실행했다(이미 만든 환경을 새 버전에 맞추는 합치기). 처음으로 실제 프로젝트에서 확인된 것: 합치기가 기존 내용을 지우지 않고 달라진 것만 반영함, 훅 경로가 자리표시 그대로 들어감, 낱개 스킬 복사 절차가 끝까지 됨(ECC의 두 스킬, 스크립트 없음을 확인하고 `SOURCE.md`를 남김), 새 형식의 배운 점으로 옮겨짐. 드러난 문제: 해당하는 디자인 도구 여럿을 스스로 "제안하지 않음"으로 뺌(고침).

- 2026-11-17: 사용자 요청으로 스킬 둘을 더했다. `improve`(이미 돌아가는 프로젝트를 살펴보고 나아질 곳을 목록으로 보여 준 뒤 고른 것만 하나씩 고침)와 `clarify`(모호한 요청에서 바라는 것을 알아냄). `AGENTS.md` 본에 모호한 요청 다루기, 쉬운 말로 말하기, 사용자가 직접 확인하는 방법 알려 주기를 더했다. 목표: Claude를 다루는 데 서툰 사람도 바이브 코딩을 잘 하게 돕는다. 시험: 결함을 심은 작은 할 일 앱에서 대화 없는 실행 5번(모델 별칭 sonnet, 어림 약 0.5달러). `improve`는 파일을 고치지 않고 심어 둔 결함 여섯 가지를 모두 목록에 올림. "여기 좀 깔끔하게 해줘"는 첫 실행에서 화면인지 코드인지를 되물어, 느낌 말은 화면 이야기로 먼저 본다는 줄을 더했고 다시 실행하니 `clarify`를 불러 화면만 정돈하고 확인 방법을 알려 줌. "삭제가 뭔가 이상해"는 `clarify`를 부르지 않고 바로 고쳤는데(증상이 코드에서 드러남) 보고가 코드 낱말 위주였다. 확인하지 못한 것: 사람이 답하는 대화형 실행, 화면을 띄워 보는 확인, 웹이 아닌 프로젝트.

## 다음 할 일

- `improve`와 `clarify`를 실제 프로젝트에서 써 보고 막히는 곳을 `docs/LEARNINGS.md`에 적는다. 특히 물음이 너무 많거나 적지 않은지, 목록의 말이 쉬운지를 본다.
- 실제 프로젝트에서 `/vibe-kit:setup`을 써 보고 막히는 곳을 `docs/LEARNINGS.md`에 적는다.
- 웹이 아닌 화면용 디자인 도구는 접근성 하나뿐이다. 라이선스가 명시된 후보를 더 찾는다(공식 마켓플레이스의 expo 등). 보류한 ECC의 SwiftUI·Compose 스킬은 빌드할 수 있는 환경에서 다시 본다.
- 채택한 디자인 도구 셋(frontend-design, impeccable, hallmark)을 실제 프로젝트에서 써 보고 `docs/LEARNINGS.md`에 적는다. 설치본(스크립트 포함)의 동작은 아직 시험하지 못했다.
- 계속 배우기 훅이 실제 작업에서 교정을 제대로 짚는지 본다(놓친 교정, 잘못 짚은 말을 `docs/LEARNINGS.md`에 적는다). 낱말 무늬는 한국어와 영어만 본다.
- 남은 후보 시험: 브라우저 확인 도구 둘(playwright, chrome-devtools-mcp)의 비교, 언어 서버 플러그인(언어 서버가 있는 프로젝트에서), security-guidance(대화형 세션에서), 커뮤니티 후보(impeccable, ui-ux-pro-max, rtk, superpowers, context7, serena, modern-web-guidance).
