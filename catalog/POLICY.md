# 반영 정책

키트의 변경은 가지와 변경 제안(풀 리퀘스트)으로 올린다. 이 파일은 그중 에이전트가 스스로 병합해도 되는 범위를 정한다. 사용자가 이 파일을 고치면 그에 따른다.

## 스스로 병합한다

형식 검증(`node scripts/validate.js`)을 통과하면 병합하고 보고에 적는다.

- `catalog/TOOLS.md`의 기록 갱신(새 후보 기록, 확인 날짜와 출처 갱신, 보류·거절 기록). 단, 상태를 "채택"이나 "퇴출"로 바꾸는 것은 아래 "사용자가 병합한다"에 해당한다.
- 이미 채택한 도구의 정보와 권장 설정 갱신.
- 오탈자와 낡은 링크 수정.
- `docs/STATE.md`, `docs/STACK.md`, `docs/LEARNINGS.md`의 기록 갱신.

## 사용자가 병합한다

사용자가 병합하는 것이 곧 승인이다.

- 새 도구의 채택.
- 채택한 도구의 교체와 퇴출.
- 훅과 권한의 변경.
- 스킬 절차와 서브에이전트의 변경.
- 서버 실행 스크립트와 그 설정의 변경.
- 이 파일의 변경.
- 파일 삭제가 들어 있는 변경.

## 디자인 분야 (변경 제안 없이 바로 올린다)

2026-11-16 사용자 지시: 디자인에서는 큰 발전이 필요하므로 플러그인과 스킬을 적극적으로 받아들이고, 좋아 보이는 것은 변경 제안 없이 올린다.

디자인 도구(화면 만들기, 점검·다듬기, 디자인 값·참고 자료, 움직임, 플랫폼별 관례)에 한해, 아래를 지키면 `catalog/TOOLS.md`의 기록·채택·교체·퇴출과 그에 따른 `adopted-tools.md` 갱신을 가지와 변경 제안 없이 기본 가지에 바로 커밋해 올린다.

1. 내용물을 직접 열어 확인하고 기록한다: 스크립트·훅·외부 연결이 있는지, 라이선스, 유지 상태, 출처 주소.
2. 시험했으면 결과를, 시험하지 못했으면 "시험 없이 채택"과 그 이유를 이유 칸에 적는다. 사람이 없는 실행은 처음 보는 코드를 설치하거나 실행하지 않으므로 시험 없이 올리게 된다.
3. 같은 세부 역할에는 채택을 하나만 둔다. 더 나은 것이 나오면 교체한다.
4. `node scripts/validate.js`가 통과한다.
5. 커밋 메시지에 무엇을 왜 바꿨는지와 되돌리는 방법(`git revert`)을 적고, `docs/STATE.md`의 실행 기록에 남긴다.

이 절이 넓히는 것은 **키트의 목록에 올리는 일**까지다. 프로젝트에 실제로 설치하는 일은 여전히 `setup`에서 사용자가 항목별로 승인한다. 디자인이 아닌 도구, 훅·권한·스킬 절차의 변경은 위의 "사용자가 병합한다"를 그대로 따른다.

남는 위험: 사람이 없는 실행이 웹에서 읽은 글만으로 도구를 목록에 올릴 수 있다. 그래서 설치 승인 때 `catalog/TOOLS.md`의 이유 칸("시험 없이 채택" 여부, 실행 범위)을 함께 보여 준다.

## 이렇게 나누는 이유

사람이 지켜보지 않는 서버에서 처음 보는 코드를 스스로 설치하면 그 코드가 사용자의 권한으로 실행된다. 그래서 실행되는 것(도구, 훅, 권한, 절차)을 바꾸는 일은 사용자가 보고 병합하고, 기록을 고치는 일만 스스로 병합한다.

## 병합 뒤

병합된 변경은 다음 주기에 효과를 확인한다. 같은 문제가 다시 나오거나 결과가 나빠졌으면 되돌리는 변경 제안을 만들고 알린다.

## 범위를 넓히는 예

사용자가 아래 같은 줄을 "스스로 병합한다"에 더하면 그에 따른다.

- 공식 마켓플레이스(`claude-plugins-official`)의 플러그인은 시험을 통과하면 스스로 채택한다.
