# 프로젝트 형태별 확인 수단

출발점이다. 프로젝트에 더 나은 수단이 이미 있으면 그것을 쓴다. 고른 줄은 이 프로젝트의 실제 명령과 대상으로 바꿔 `AGENTS.md`의 "확인 수단"에 적는다.

| 결과물 형태 | 확인 수단 | 통과로 보는 것 |
|---|---|---|
| 웹 | 브라우저로 띄워 스크린샷과 콘솔 오류 확인 | 바꾼 화면이 의도대로 보이고 콘솔에 새 오류가 없다 |
| 모바일 앱 | 에뮬레이터나 시뮬레이터에서 실행해 화면 확인 | 바꾼 화면까지 가는 흐름이 막힘 없이 된다 |
| 데스크톱 앱 | 실행해 주요 흐름을 따라가 확인 | 바꾼 기능의 흐름이 처음부터 끝까지 된다 |
| 명령줄 도구, 스크립트 | 예시 입력에 대한 출력과 종료 코드 비교 | 출력과 종료 코드가 기대와 같다. 잘못된 입력에는 0이 아닌 종료 코드와 안내가 나온다 |
| 라이브러리 | 자동 테스트 | 관련 테스트와 전체 테스트가 통과한다 |
| 서버 | 자동 테스트, 실제 요청과 응답 확인 | 테스트가 통과하고, 띄운 서버가 예시 요청에 기대한 응답을 준다 |
| 데이터 분석 | 표본 검산, 합계와 건수 대조 | 손으로 계산한 표본과 결과가 같고, 입력과 출력의 건수·합계가 맞는다 |
| 게임 | 실행해 조작과 화면 확인, 가능하면 엔진의 자동 테스트 | 바꾼 조작이 의도대로 되고 자동 테스트가 통과한다 |
| 직접 실행할 수 없는 대상(임베디드 등) | 빌드 성공과 정적 검사 | 빌드와 정적 검사가 통과한다. 실기기 확인은 사용자에게 부탁할 항목으로 적는다 |

한 프로젝트가 여러 형태에 걸치면(예: 서버와 화면) 해당하는 줄을 모두 쓴다.

확인 수단을 실행할 도구가 이 컴퓨터에 없으면(예: 에뮬레이터 없음) 그 사실을 `AGENTS.md`에 적고, 실행할 수 있는 가장 가까운 수단(빌드, 정적 검사, 자동 테스트)과 사용자에게 부탁할 확인을 나눠 적는다.
