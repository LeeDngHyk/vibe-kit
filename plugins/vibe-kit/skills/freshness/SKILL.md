# freshness: 최신 상태 유지

기억보다 현재 문서를 기준으로 일한다. 도구와 형식은 계속 바뀌고, 모델이 기억하는 내용은 낡았을 수 있다.

기록 파일은 `docs/agent/STACK.md`다. 없으면 `/vibe-kit:setup`을 먼저 실행하자고 안내하고 멈춘다.

세 가지 방식이 있다. 새 기능·도우미 코드·의존성을 만들려는 참이면 "만들기 전에 먼저 찾아본다"를, 인자가 `audit`이거나 마지막 점검에서 7일이 지났으면 "정기 점검"을, 그 밖에는 "쓰기 전 확인"을 한다.

## 만들기 전에 먼저 찾아본다

코드를 새로 쓰기 전에, 같은 일을 하는 것이 이미 있는지 찾는다. 직접 만든 코드는 계속 돌봐야 하고, 잘 유지되는 기존 것이 대개 더 많은 경우를 이미 다뤘다.

작은 일(도우미 함수 하나, 몇 줄짜리 변환)은 1번과 2번만 머릿속으로 빠르게 본다. 기능 하나를 통째로 만들거나 의존성을 더하는 일은 아래를 모두 한다.

1. **이 저장소 안**: 비슷한 일을 하는 코드나 테스트가 이미 있는지 이름과 낱말로 찾는다. 있으면 그것을 쓰거나 넓힌다.
2. **이미 쓰고 있는 의존성**: 프로젝트가 이미 들인 라이브러리나 표준 라이브러리에 그 기능이 있는지 본다. 새 의존성보다 먼저다.
3. **이 프로젝트 생태계의 패키지 저장소**: 같은 일을 하는 패키지를 찾는다. 유지 상태(최근 릴리스), 라이선스, 딸려 오는 의존성의 크기를 본다.
4. **이미 연결된 도구**: 이 프로젝트나 컴퓨터에 이미 있는 스킬, 플러그인, 외부 연결이 그 일을 하는지 본다.
5. **공개된 구현**: 잘 유지되는 공개 저장소에 참고할 구현이나 본이 있는지 본다.

찾을 것이 많으면 `vibe-kit:researcher` 서브에이전트에 맡긴다. 쓸 수 없는 통로(패키지 저장소 조회 불가, 웹 조회 불가)는 건너뛰되, 건너뛴 곳을 보고에 적는다. 찾지 않은 곳을 찾은 것처럼 적지 않는다.

찾은 결과로 넷 중 하나를 고른다.

| 찾은 것 | 고르는 것 |
|---|---|
| 딱 맞고 잘 유지되며 라이선스가 맞는 것 | **그대로 쓴다** |
| 대부분 맞는 좋은 바탕 | **감싸 쓴다**: 들이고 얇은 코드만 더한다 |
| 조금씩 맞는 작은 것 여럿 | **엮어 쓴다**: 두세 개를 묶는다 |
| 맞는 것이 없음 | **직접 만든다**: 찾으며 본 것을 참고해 가장 작게 만든다 |

새 의존성을 들이는 선택은 사용자의 승인을 받는다(후보와 이유를 제시). 저장소 안의 것을 쓰거나 직접 만드는 선택은 스스로 정하고, 무엇을 찾아봤고 왜 그렇게 골랐는지 한두 줄로 보고에 남긴다.

**완료 조건**: 찾아본 곳, 찾은 것, 고른 것과 이유를 말할 수 있다. 새 의존성을 골랐으면 아래 "쓰기 전 확인"까지 마쳤다.

## 쓰기 전 확인

외부 라이브러리, 명령줄 도구, API, 모델 이름, 가격, 지원 조건을 쓰려 할 때마다 한다.

1. `STACK.md`에서 그 항목을 찾는다. 확인 날짜가 오늘로부터 30일 이내면 그대로 쓴다.
2. 줄이 없거나 30일이 지났으면 공식 문서(공식 사이트, 공식 저장소의 릴리스 안내, 패키지 저장소의 항목)를 열어 최신 안정 버전과 지금 쓰려는 기능의 사용법을 확인한다. 블로그나 질문 답변 글은 실마리로만 쓰고 근거로 삼지 않는다.
3. `STACK.md`의 줄을 고치거나 더한다: 항목, 쓰는 버전, 확인한 최신 버전, 확인 날짜(오늘), 출처 주소, 메모.

다음 경우에는 기록 날짜와 상관없이 다시 확인한다.

- 오류 메시지가 API 변경을 시사한다(없는 함수, 바뀐 인자, 폐기 경고).
- 처음 다뤄 보는 프레임워크나 라이브러리다. 공식 시작 안내와 현재 버전의 변경 사항을 먼저 읽는다.
- 가속기(GPU 등)의 커널 수준 성능 최적화 같은 저수준 영역이다. 이 영역은 기억의 신뢰도를 더 낮게 보고 문서를 먼저 읽는다.

새 의존성이 필요하면: 최신 안정 버전, 유지 상태(최근 릴리스와 미해결 문제의 흐름), 라이선스를 확인한 뒤 후보 두세 개와 이유를 제시하고 승인을 받는다. 승인 전에는 설치하지 않는다.

**완료 조건**: 쓰려는 항목의 줄이 `STACK.md`에 오늘 날짜와 출처 주소와 함께 있다. 확인하지 못했으면 메모에 "확인 실패: <이유>"라고 적고 사용자에게 알린다.

## 정기 점검 (주 1회)

1. **의존성의 새 버전과 보안 경고**: 이 프로젝트의 패키지 관리 도구가 제공하는 "낡은 의존성 보기"와 "보안 점검" 명령을 실행한다. 명령 이름은 그 도구의 현재 문서에서 확인한다. 그런 명령이 없으면 패키지 파일의 주요 의존성을 패키지 저장소에서 직접 확인한다.
2. **릴리스 안내**: 이 프로젝트가 쓰는 주요 언어·프레임워크·라이브러리·도구의 릴리스 안내를 읽고, 이 프로젝트가 실제로 쓰는 기능에 영향이 있는 것만 고른다. 항목이 많아 조사가 길어지면 `vibe-kit:researcher` 서브에이전트에 맡긴다.
3. **기록**: 결과를 `STACK.md` 표에 날짜와 출처 주소와 함께 적고, 첫머리의 "마지막 점검"을 오늘 날짜로 바꾼다. 기록은 승인 없이 한다.
4. **제안을 두 묶음으로 나눈다**:
   - 바로 적용해도 되는 작은 갱신: 수정·보안 패치, 호환이 유지되는 작은 버전.
   - 이행 메모가 필요한 큰 버전 변경: 무엇이 바뀌는지, 이 프로젝트의 어디를 고쳐야 하는지, 위험과 되돌리는 방법.
5. **적용은 승인 뒤에 한다**. 적용한 뒤에는 프로젝트의 확인 수단(`AGENTS.md`)을 실행해 통과를 확인하고, 실패하면 되돌리고 알린다.
6. `docs/agent/STATE.md`의 "다음 할 일"에 승인을 기다리는 갱신을 적는다.

사람이 없는 실행(서버의 정기 실행)에서는 1~4와 6까지만 하고 적용하지 않는다. 기록 변경은 새 가지에 커밋해 변경 제안으로 올린다.

**완료 조건**: "마지막 점검"이 오늘 날짜이고, 두 묶음의 제안(없으면 "없음")이 보고에 있다.
